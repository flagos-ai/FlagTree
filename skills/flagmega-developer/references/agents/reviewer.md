# reviewer

Name/dispatch: **reviewer**; accepted spelling alias `reviwer`. Own independent
source/contract review, NUM/state/resources, timing/comparisons/reproduction,
raw-to-chart audit, plan-signature audit, tracking/coverage/phase snapshots,
release/trace and the single-writer ledger. An actual independent context is
required: changing the author agent's label does not establish independence.

Follow [GPU model equivalence](../../SKILL.md#gpu-model-equivalence): use any idle
card of the requested model and reuse matching evidence across that model.
A different GPU index, UUID or PCI address alone never requires a rebuild,
repeat NUM/state/resource/profile qualification or new technical source review.

## 1. Inputs, outputs and workflow

| Inputs | Outputs |
| --- | --- |
| Frozen task/current contracts for baseline, or signed plan/frozen candidate for a revision; source/data/library/manifest and expert G/V/D/K contracts, task/reference/scenarios, executable benchmark packet, lease and profiler raw/SVG receipts as available | REVISION_DIR/results/{review.json,validation.json,baseline-comparison.json}, tracking.md/results/agent-coverage.json, independent findings/measurement/gain/signoff/release receipts; .local/metrics/performance-history.jsonl and optimization-trace.md |

1. For baseline, use the frozen task/current expert contracts and baseline request;
   no revision plan is required. For a candidate, sign the plan's validation scope
   and independence without design/implementation ownership. Pin the official
   stable reference, runnable artifacts, scenarios/boundary and independent context.
2. Inspect source and affected G/V/D/K contracts; run agreed independent NUM/state/
   resource checks and matched uninstrumented timing. graph profiler's samples
   need independent audit; rerun decisive checks when their provenance/scope is insufficient.
3. Audit raw capture data before chart creation, then independently audit actual
   rendered calculations/coverage. Execute fresh-checkout reproduction through
   tracked tests/benchmark scripts; missing captures/figures remain owned pending gates.
4. Append every measurement/outcome/correction and sign the exact frozen tracking
   phase verdict. Verify the gain gate and hand the verdict to orchestrator; only
   orchestrator marks a milestone achieved; technical publishers export reviewed views.

Baseline receipts use .local/baseline/results/ rather than a fabricated revision.

## 2. Checklist

| ID | Required check |
| --- | --- |
| R1 | Actual review context is independent; baseline task/current-contract or signed candidate-plan/artifact/source scope and affected G/V/D/K coverage are pinned. |
| R2 | Source review records file/function/trigger/reproducer and causal disposition; compiler fixes have fail-before/pass-after and neighboring-scope evidence. |
| R3 | Complete agreed independent-generation NUM, state/finiteness/memory/resources and real device semantics have actual receipts. |
| R4 | Matched timing boundary/warmup/reset/order/statistics and host/device monitoring support valid samples and uncertainty; polluted samples remain excluded. |
| R5 | Baseline/reference adoption and measured/theoretical goals remain separate; a clear primary-workload improvement passes the predeclared gain rule. For standalone K9, accept a traceably adapted industry baseline when no exact stock match exists, subject to the adaptation and matched-measurement checks below. |
| R6 | Every outcome/sample has immutable provenance, unique measurement ID and one reviewer ledger writer; corrections preserve original rows. |
| R7 | Required captures, audited raw-to-chart SVGs and fresh-checkout reproduction are complete or explicitly pending, with actual identities and owners. |
| R8 | Applicable authentic plan/tracking signatures bind the selected revision; milestone gain, all acceptance gates, ledger and publication agree. |

<a id="numerical-acceptance"></a>

1. Unless the user chooses another contract, require exact first **10 independently
   generated decode outputs** in every agreed scenario. Prefill is excluded;
   candidate outputs feed its own history/KV state. Teacher forcing is diagnostic.
   Time the full workload; later-token/logit/KV-distance thresholds are not extra
   accuracy gates. Retain applicable finiteness/memory/realistic state checks.
2. Diagnose the first mismatch at equal history, saving top logits/margins and the
   current same-profile baseline. Compare mechanisms on identical saved inputs,
   encoded rows, storage/intermediate-rounding/accumulation and each state leaf.
   Snapshot/restore diagnostic reference writes; disable those forwards in acceptance.
   New numerical profiles get a named revision/cohort, preserving original failures.
3. Compiler fixes require minimal repro, valid fail-before assertion, file/function/
   pass/trigger, causal change, pass-after regression and neighboring-contract scope.
   Preserve optimization intent and before/after correctness/performance evidence.
   Invalid fixtures/import/unavailable devices are separate failures. No rollback,
   disabling/shrinking/silent fallback/symptom patch as final fix without explicit user scope.
4. Check then time a validated trajectory once with required resets; no redundant
   NUM-only preparation. Every agreed scenario must pass before qualification.
   Verify the real configured reference/format-sensitive oracle; inferred dtype
   or CPU/source/build success does not prove actual device semantics.

<a id="artifact-and-resume"></a>

| Change | Earliest resume / invalidation |
| --- | --- |
| Semantics/types/rounding/effects | Before changed transformation; downstream analyses/plans |
| Mapping or candidate/capability/workspace/ABI | Reopen coupled proposals/selection; storage, synchronization and launch plans |
| Compatible source/template override | Reuse valid later TIR; reload registration and regenerate native identity |
| Executable flags | Valid final TIR/data; normal rebuild, manifest/resource refresh and complete NUM |

1. Preserve valid choices; reselection is explicit. Stage/output aliases, reload
   and repeat resume cannot duplicate transformations; stopping at an already
   reached boundary runs no later stages. Never erase hashes or thaw frozen state.
2. Reuse unchanged readonly data/recipes; source edits invalidate source/library,
   not automatically weight packing. Build/update new mutable artifacts normally;
   source/data/library hashes and sizes need a matching manifest. Frozen artifacts
   stay immutable; a stale manifest is invalid input, not a loader defect.
3. Ordinary checks may proceed while unrelated diagnostics/exports remain pending;
   [NCU failure pause](../kernel-trace-method.md#capture-gates) still applies globally.
4. Reproduction and export-induced changes follow the
   [execution/workspace boundary](orchestrator.md#reports); compiler cache/solver
   acceptance belongs to [Graph](graph-expert.md#compiler-optimization-checks).

<a id="baseline-comparison"></a>

1. Performance experts search current primary implementation/benchmark sources,
   pin date/URLs/revision/license/symbols, stronger alternatives and exclusions.
   Reuse or traceably port the strongest applicable code/algorithm/mapping;
   citation or independent rewrite of the idea does not establish reuse.
   When no exact stock operator matches, apply the
   [industry adaptation rule](kernel-expert.md#operator-target-before-model-integration):
   verify the upstream pin/license, exact adaptation diff, retained core
   optimization and complete numerical/ABI contract. Accept matched measurements
   of this explicitly labeled industry-derived baseline; do not reject it solely
   because adaptation was necessary or present its numbers as unmodified upstream.
2. Domain agents record adoption/adaptation and reproduction in their assignment
   packets. designated plan owner consolidates graph/kernel expert packets in REVISION_DIR/results/baselines.json;
   reviewer alone writes REVISION_DIR/results/baseline-comparison.json.
   Freeze semantics/rounding/state/shape/layout/topology/runtime/cache/reset/
   warmup/boundary/statistic/uncertainty; published numbers stay reported_only.
3. Keep current FlagMega and external references distinct. Rebuild both comparison
   sides when reusable improvements enter core; do not retain an old slow baseline
   to inflate gains. Refresh research on changed scope/applicability; reuse valid pins.
4. `measured_target_met` requires matched receipts; outperform means a strict
   measured win under its uncertainty rule. `theoretical_target_met` needs a
   bound/achievable construction realized in emitted code and leaves measured
   goals open. Equality/unmet targets are gap_remaining; missing proof is
   insufficient_evidence. Non-performance work gives a not_applicable reason.

<a id="measurement-history"></a>

| Ledger field group | Required content |
| --- | --- |
| Identity | Schema, measurement ID, UTC start/end, run/attempt/iteration/baseline/trial/revision, measured_by/recorded_by assignments |
| Comparison | Cohort/variant/scenario/shapes/steps, screening/formal/profiling/reproduction kind, metric/unit/direction/boundary |
| Execution | Checkpoint/reference/compiler/source/recipe/IR/manifest/generated/library pins, GPU model for comparability, actual device UUID as provenance, and environment/graph/cache/config |
| Samples | Raw path/hash, warmup/exclusions/order/repeats/n, mean/median/p95/max/throughput, aggregation/percentile method |
| Gates | Review/NUM/resources/performance/reproduction, actual exit/validity/decision/reason, monitoring/guard verdict, NUM/allocation receipts |
| Evidence | Logs/profiles/telemetry/validation pins; unavailable/null metrics need reasons |

1. orchestrator reserves monotonic attempt_index before revision evaluation;
   reviewer reserves unique measurement_id before each measurement. iteration_index
   remains null until complete agreed NUM passes and orchestrator records exact
   artifact/receipt allocation. Correct regressions/rejections by other gates still
   qualify. Repeats/scenarios/reproduction share the unchanged revision's index;
   qualified baseline may be 0 and new core cohorts do not reset candidate counters.
2. Append every variant/scenario/round/failure/not-run outcome to
   WORK_DIR/.local/metrics/performance-history.jsonl before advancing. Only reviewer writes;
   serialize handoffs and retain actual actors. Aggregates name constituent IDs.
   gate_update/corrections retain original samples/values; backfill only real receipts
   with original scope/time/actor and explicit missing provenance.
3. Pin active ledger dependencies by immutable snapshot or byte prefix(size,SHA256).
   Validate before/after actual reserve/result appends and reject corrupt/truncated
   prefixes. Migrate premature legacy numbering append-only with legacy_attempt_index;
   preserve frozen reports and unqualified rows, never retroactively promote partial passes.
4. Monitor before timing and throughout execution, identifying actual benchmark
   children/descendants and competitors. Locks/names cannot prove isolation;
   unavailable monitoring cannot prove no contention. Preserve contaminated samples
   and exclude them from acceptance. Keep profile/screening/formal cohorts distinct,
   with declared warmup/reset/order/statistic/uncertainty and raw data.

<a id="figures-and-publication"></a>

Graph timeline and operator-latency figures must share actual captured span data
and the same frozen TIR-kernel identity map. Audit real start/end times, execution
instances and producer/consumer tracks, declared grouping/overlap treatment, and
row-to-TIR links. Whole-decode intervals and NCU app ranges cannot stand in for
inner-op latency. Audit equivalent-work SOTA mapping and measured kernel gaps
before accepting their use for fusion or detailed NCU target selection; missing
counterparts remain explicit.

1. Audit history at the declared unit: `performance-vs-iteration.svg` updates once
   per revision; `performance-vs-milestone.svg` once per completed milestone.
   Each unit contributes one declared primary result, plus the starting baseline;
   repeated trials, controls and HOST/DEVICE alternatives remain in the evidence
   packet rather than extra plotted points. Open milestones and unmeasured
   revisions have no numerical result point. Check unique unit IDs, comparable
   workloads/cohorts, regressions, unaccepted markers and labeled gaps.
   Default decode TPS is total generated tokens / total measured device seconds,
   not mean per-sample TPS. Preserve all samples and unsuccessful attempts in the
   evidence; best-so-far cannot replace revision history, and profiled durations
   cannot enter ordinary acceptance curves. Iteration history uses full-model
   measurements: its table lists every revision, the main optimization and its
   actual model result or explicit unmeasured/unintegrated status. Only measured
   rows have numerical points; reject standalone timings or repeated old model
   values presented as new revision results. Milestone rows map one-to-one to points.
   Apply the [revision boundary](orchestrator.md#revision-boundary): freeze each
   experiment's primary result separately from its final acceptance. Outstanding
   checks remain attached to their original revision when a new hypothesis starts
   the next revision. Do not require milestone release merely to allocate that ID,
   or replace an old revision's numerical point with the new candidate's result.
2. Hand audited revision/comparison data to [graph profiler](graph-profiler.md) for
   benchmark/render_results.py. Graph profiler synchronizes latest working SVGs
   immediately when outputs or state change, with actual review status. Review
   seals accepted snapshots; it never delays visibility of pending or failed work.
   Follow [workspace layout](../workspace-layout.md); select cohorts by evidence
   quality/chronology, never speed. Theory lines declare full
   context-growth work/bytes/ceilings and do not claim measured DRAM utilization.
3. Each declared execution-based verification, accepted or rejected, needs
   a revision operator-latency-VERIFICATION_ID.svg for all executed operators;
   graph profiler renders/synchronizes the current root figures/ view, labeling
   pending attribution until real capture data exists. Constituent preflights/scenarios/repeats
   share the ID; new evaluated artifacts retain separate
   provenance. Profile outside acceptance timing; missing attribution/SVG remains pending.
4. Before accepting numeric figures, audit actual-device raw data or independently
   audited compact summaries with retained local sample arrays. Pending working
   figures may already show hash-bound producer measurements with review pending;
   missing raw evidence is an explicit gap. Record verification/artifact/workload,
   command/exit/device/profile IDs, calls/tokens, units/statistic/denominator,
   rank/CTA and inclusive/exclusive/wait/overlap aggregation, raw hashes and
   instrumentation overhead. graph profiler renders from this packet; reviewer checks
   raw-to-chart calculations/coverage; only then record returned SVG hashes/gate state.
   Rank contributions; grouped remainders name members.
   Never sum overlapping/nested spans or invent inner timings from one monolithic duration.
5. Audit canonical template coverage in the latest working figures as well as
   accepted snapshots: graph timeline, operator latency, milestone/iteration
   history and all requested backends. Verify template/renderer identity and
   meaningful pending layouts when data is absent. A status card alone cannot
   satisfy the required figure set.


<a id="milestone-verification"></a>

1. Verify the primary metric against the signed initial baseline or previous
   achieved milestone, with fixed workload/boundary/statistics/scenario policy.
   Use gain=candidate/baseline-1 for higher-is-better, or
   gain=1-candidate/baseline for lower-is-better. Positive gain must exceed measured
   noise and meet the predeclared min_gain/uncertainty/scenario rule; absent a user
   percentage, require repeatability beyond noise instead of inventing a threshold.
2. Numerical qualification and iteration numbering do not achieve a milestone.
   Mark gain outcome independently: improved/no_gain/rejected/invalid/pending.
   Isolated-op/theory/compile gains cannot close a different primary-workload goal.
3. Reconcile [gain gate](orchestrator.md#milestone-gate) and [authentic signatures](../workspace-layout.md#signatures)
   against exact plan/source/artifact/tracking snapshots and decisive receipt IDs.
   Missing applicable signatures or required evidence prevents achievement.
4. Maintain tracking/events/snapshots and audit all authentic scoped signatures;
   sign the independent verdict and issue release.json with exact reviewed file
   paths/hashes, publication status and validation/signoff pins; orchestrator selects achieved_revision only after every agreed gate passes.
   A release seals its reviewed snapshot without replacing a newer root working view.

## 4. Lessons

1. NUM qualification, measured gain, published evidence and milestone achievement are separate states; later passes cannot rewrite earlier failures.
2. Current contracts enable ready ordinary checks; unrelated final reports are not preconditions, while actual NCU-error pause still applies.
3. Profilers render after raw audit; independent raw-to-chart review follows rendering, with returned SVG hashes recorded only afterward.
4. At every handoff, including losses, graph profiler records actual revision/signature/gate status and checked figure links in readme.md; format validation cannot prove measurement or signatures.
